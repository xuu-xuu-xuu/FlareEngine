# 命名规范

Flare 的新代码沿用所在模块的英文标识符。给新功能取名时，先查同一模块对这个概念的叫法。名字一旦写入项目文件、跨语言接口或资产绑定，调用方和读取方就依赖它的完整拼写和大小写。

## 新代码的默认写法

下表把源码中常见的写法定为新增代码的默认值。扩展已有接口族时，沿用该接口族的命名，包括缩写的大小写。

| 对象 | 写法 | 仓库实例 |
| --- | --- | --- |
| C++ 类型、枚举项、公开常量 | 各单词首字母大写（PascalCase）。类型和状态用名词，数值常量写出含义。 | [EnvironmentPhase、FixedPreTick](https://github.com/xuu-xuu-xuu/FlareEngine/blob/8b0eaed34421bffbeb5c1eee837c14a26d43e283/Source/FunctionLayer/Runtime/Environment.h#L12)、[MaximumLinearSpeed](https://github.com/xuu-xuu-xuu/FlareEngine/blob/8b0eaed34421bffbeb5c1eee837c14a26d43e283/Source/FunctionLayer/Physics/PhysicsWorld.h#L63) |
| C++ 函数、方法 | PascalCase。执行动作用动词开头，判断可用 `Is…`，已有的查询接口可以直接用名词。 | [SetPhysicsService](https://github.com/xuu-xuu-xuu/FlareEngine/blob/8b0eaed34421bffbeb5c1eee837c14a26d43e283/Source/FunctionLayer/Runtime/Environment.h#L33)、[IsEngineFeature](https://github.com/xuu-xuu-xuu/FlareEngine/blob/8b0eaed34421bffbeb5c1eee837c14a26d43e283/Source/FunctionLayer/Runtime/FeatureComponents.h#L28) |

## 跨模块交接

开工前，把新增的公开类型、函数签名、持久化键或事件标记的准确拼写放进任务卡，并给出已有定义或约定它的文件位置。生产者、消费者和测试样例引用同一份定义。项目专用名称由项目的契约或资产清单维护。

评审改名时，从名字的读取方追到已有数据。例如把 `Spin` 改成另一个类名，只要显式 `[F_Script("renderingstudio.spin")]` ID 仍然相同，绑定中的 `Type` 就仍能标识它。若同时把暴露字段改名，旧绑定的 `Fields` 里仍保存原拼写，需要同步迁移并用旧项目重开验证。
